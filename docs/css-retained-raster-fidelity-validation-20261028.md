# CSS 连续帧缓存与栅格精度增量验证（R18）

本轮接续 [R17 的分数位置缓存诊断](css-motion-reference-boxes-validation-20261028.md#原生交互与仍开放的像素问题)，修复 Software／Metal 的捕获范围、栅格相位和镜像文字问题。**正式全量 24,189／24,189 通过，4,986 对实际／参考图严格一致；不透明背景与原生 Metal 窗口的剩余 RGB 差异仍开放。** 完整 CSS、M1 全部组合、完整 Ruby、G0／E2 及跨平台验收继续为部分完成。

## 实现行为

- 缓存捕获使用与直接绘制相同的元素变换和绘制偏移计算顺序。`Visual` 记录实际 X／Y DPI、物理像素相位和镜像方向；整数物理像素位移复用缓存，分数相位、DPI 或方向变化重新捕获。没有通过关闭缓存消除差异。
- Software 与 Metal 将捕获范围向外取整到物理像素边界，同时保存请求逻辑矩形与实际纹理之间的规范化偏移和范围。合成还原这些边距；仅在一比一、物理像素网格对齐时使用最近邻采样，普通缩放继续使用原有重采样路径。
- 两个后端分别修正镜像捕获后的像素／UV 方向，避免捕获和合成重复翻转。文字遇到负 X／Y 缩放时保留带符号的原生矩阵，避免缩放被展平后字形消失。
- Software 在透明目标上混入非透明源像素时直接保留源 RGBA，避免无必要的预乘／反预乘舍入。普通混合路径继续处理已有目标颜色；不透明背景上的严格恒等问题尚未全部解决。
- 捕获前检查有限数值和有效物理范围，超出视口的捕获继续回退。失败时平衡变换栈并保留已有有效快照；缓存预算、生命周期与跨目标限制继续沿用。D3D12 和自定义绘制上下文通过接口默认实现保留原有路径，未获得 Windows GPU 验收。

产品改动位于 `Visual.cs`、`IOffsetDrawingContext.cs`、`RenderTargetDrawingContext.cs`、Software 后端头文件／实现和 Metal 渲染目标。新增回归为 [CssRetainedRasterTests.cs](../tests/Jalium.UI.MacOS.Tests/CssRetainedRasterTests.cs)。本轮没有增加 CSS 语法入口。

## 反向对照与测试修正

将**同一最终测试程序集**换载逐一核对的八个 R17 产品程序集和 R17 原生／shader 载荷，结果为 **390 失败、96 个控制项通过**，0 超时。父进程、Metal 子进程和正式全量的测试 SHA 均有记录。390 是用例数，不是互不相同的产品缺陷数。见 `negative-final/payload-identity.json` 与 `negative-final/summary.json`。

测试开发中纠正了三个会影响结论的前提：Ruby 在移动布局后可能再次标记内容脏，不能认为它永远不参与缓存；原生镜像捕获必须覆盖 Ruby 的实际 ink，手动捕获测试使用 24 DIP 边距；早期镜像图的边框相同但文字为空，已增加两侧字形存在断言并修复产品文字矩阵。早期运行与 v1／v2 原生页保留为诊断记录，不替代最终 `signed-recorded-focused/`、`final-full/` 和 `*-verified/` 证据。

## 构建与载荷身份

托管使用仓库 `.tools/dotnet/dotnet`，SDK 10.0.300／运行库 10.0.8、隔离 `JaliumBuildRoot`、关闭共享编译。七个代码／测试输入、九个托管程序集和十个原生／shader 文件自正式全量开始后未改变；专项、全量及 Metal 子进程逐项哈希一致。全量进程 `vmmap` 中实际加载的七个原生库均来自本轮 `native-fixed/`。

本轮在独立 CMake／Ninja 根重新编译原生载荷，原生子树输入清单 771 个。CMake 保留了旧 R11 冻结根的部分 audio 路径；16 个实际使用的 audio 源／头文件已与本轮候选逐字节核对相同。DXC 和四个 SPIRV-Cross 静态库为本机既有依赖，四个实际引入的外部头文件及五个库另有 SHA；两个 metallib 与 R17 相同、直接复用。**重新编译了 Jalium 原生库，不表示重新构建了所有第三方依赖。** 详见 `native-final/source-inputs.json`、`external-dependencies.json` 和构建命令。

构建无错误。相对 R17，唯一诊断位置 99→100、文件诊断组 66→67；新增一项 `IOffsetDrawingContext.cs` 的 CS0419，来自新增重载后 XML `cref` 名称歧义，属于非运行时文档警告，尚未清理。既有 `Visual.cs` 两项可空警告仅行号移动。不能报告“无新增警告”。

R17／R18 的 23,684 个共享精确名称中位时长合计约 1,522.9→1,946.8 秒，新增用例约 203.5 秒。R18 全量与额外诊断及原生 UI 有重叠，不作性能提升或无性能回归声明。一项文本命中用例达到“增加至少一秒且八倍”的阈值；最终载荷定向复跑其 64 项全部通过，该项约 0.329 秒，未再达到该阈值。长 Ruby 与整体应用仍需受控性能测试。见 `duration-comparison.json`。

## 仍开放的像素边界

以下诊断**不包含在正式严格像素通过口径中**：

| 不透明白底探针，每组合 72 对 | R17 严格相同 | R18 严格相同 | 最大通道差值 R17→R18 |
| --- | --- | --- | --- |
| Software／Impeller | 30 | 36 | 175→1 |
| Metal／Impeller | 18 | 18 | 97→2 |
| Metal／Vello | 18 | 18 | 97→2 |

相同探针及各自载荷已核对，严重重采样差异缩小，但不能把剩余一至两个通道值差异当作严格通过。正式新增用例以透明目标上的独立参考为口径，不是完整不透明背景合成验收。另有 CPU 翻转标准帧与镜像原生字体的诊断受 hinting／栅格化影响，不作为严格参考，也未用于放宽正式比较。

原生页内容区域 `(25,130)-(1075,550)`：Software 初始与两次恢复均严格相同；Metal 初始与 padding 往返后恢复有 **6,747 个 RGBA 字节不同、最大通道差值 7**，完成其他操作后的最终恢复又与初始相同。该差异尚未完全隔离，不能由离屏通过推导原生所有初帧／稳定帧一致，也不能直接归因于上述不透明探针的舍入。详见 `live-ui-summary.json` 与 `opaque-probe/comparison.json`。

下一步先分离原生 Metal 的直接绘制、命令录制、纹理合成与背景混合，建立同一窗口连续帧的可重复参考，再扩展字体、透明度、缩放、裁剪和 DPI 组合。M1 的全部路径坐标盒、SVG 引用、完整路径／形状插值，完整 Ruby 盒模型与文档／编辑器组合，G0／E2 及 Windows／Linux／设备验收继续按 [团队计划](css-implementation-plan.md)推进。
