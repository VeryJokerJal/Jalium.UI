# macOS Window 与无障碍

本任务仅维护 Window 行为和 macOS 无障碍，并精简相关实现与验证流程。

## 保留的能力

- 创建、显示、隐藏、关闭、取消关闭、重开及对象销毁。
- 位置、大小、DPI、最小／最大尺寸、最小化、缩放、全屏与还原。
- 激活、键盘焦点、owner／模态窗口、标题栏与系统窗口菜单；包括右键打开、命令可用状态、取消和执行。
- 键盘、鼠标、输入法、编辑菜单及 popup 的窗口归属和焦点衔接。
- AX 树、角色、名称、值、边界、焦点、选择、操作和变更通知；保留缓存身份、销毁及跨线程安全。

## 精简方式

- 无障碍窗口快照只在创建／销毁桥接时更新。通知复用不可变快照，保留原来的通知范围与处理顺序。
- 当前线程直接发布通知；只有跨线程投递才创建闭包。保留通知合并、失效对象检查及原有事件接收方。
- 移除组合 NuGet 包、跨作业原生归档、额外 Intel SDK 生产作业和第二套 PackageSmoke。
- SDK 保持单 RID 复制／打包，保留轻量的 Metal 资源目标，避免把构建 CPU 的原生资源塞进程序集。
- 保留现有 Window／AX 专项与系统菜单检查；窗口功能不因精简而降级。

## 本轮验证

- 系统菜单原生 26 项检查通过，现有宿主 4 组检查通过；Window／AX 两组原生套件通过。
- 368 项托管焦点、popup、自定义控件、可见性和通知检查通过，零失败／跳过。
- 相同冻结工作区和 ARM 主机中，每万次通知分配从单窗口 4.80 MB／8 窗口 7.60 MB 降为 3.84 MB，分别减少 20%／49.5%。三次测量中位耗时分别从 5.27／8.49 ms 变为 4.35／7.64 ms；这是局部基准，不代表整个应用速度。
- 单 RID 包仍包含所选架构的 8 个动态库和 3 个 Metal 资源；文件哈希匹配，app 中只有 8 个原生文件，深层签名检查通过。
- CUA 实际读取到右键系统菜单的 Minimize、Zoom、Enter Full Screen 和 Close；通过 AX 写入文本并查看截图，中文、emoji 与 Miii 正常显示。没有据此宣称物理键盘、VoiceOver 或完整菜单视觉验收。

## 验证边界

本轮结果在 PR 中记录。通知基准是同一份冻结工作区、同一 ARM 主机的局部测量，不能代表整个应用的启动、内存或所有交互性能。

原生与托管专项、实际截图、辅助树查询和操作分别记录。VoiceOver 实机、物理输入以及多显示器／Spaces 的完整组合继续按实际证据验收。Intel 26 的独立 NSWindow 最小化通知基线仍需单独解决。
