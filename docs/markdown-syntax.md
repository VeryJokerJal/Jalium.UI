# Markdown 控件支持的语法

`Markdown` 的解析器（`MarkdownParser` + `MarkdownInlineParser`）对齐
[CommonMark](https://spec.commonmark.org/) 与
[GitHub Flavored Markdown](https://github.github.com/gfm/) 的常用部分。
本文列出支持范围与几处刻意的取舍。

## 块级

| 语法 | 说明 |
| --- | --- |
| ATX 标题 `# … ######` | 支持闭合序列 `### 标题 ###`；`#NoSpace` 与七个以上 `#` 是普通段落 |
| Setext 标题 `===` / `---` | 接在段落后面，`===` 是一级、`---` 是二级；前面没有段落时 `---` 仍是分隔线 |
| 段落 | 行内的软换行折成空格，行尾两个空格或反斜杠是硬换行 |
| 围栏代码块 ` ``` ` / `~~~` | 记录语言标识；围栏自身的缩进会从每行内容里扣掉 |
| 缩进代码块 | 四个空格缩进，结尾空行退还给外层 |
| 块引用 `>` | 支持懒惰续行：不带 `>` 的续行仍属于引用里那个没结束的段落 |
| 列表 `-` `+` `*` `1.` `1)` | 任意层嵌套；按标记实际宽度回退缩进（`1. ` 与 `- ` 的内容起点不同） |
| 任务列表 `- [ ]` / `- [x]` | GFM |
| 松散/紧凑列表 | 空行分开的同级项属于同一个列表，只是 `IsLoose` 为真 |
| 表格 | GFM；分隔行的列数必须与表头一致，支持 `:--` `:-:` `--:` 对齐与 `\|` 转义；行按表头列数补齐或截断 |
| 分隔线 `---` `***` `___` | |
| 脚注定义 `[^label]: …` | GFM 扩展；按定义出现顺序编号 |
| 链接引用定义 `[label]: dest "title"` | 不产生可见内容 |
| HTML 块 | 见下方「原始 HTML」 |

## 行内

| 语法 | 说明 |
| --- | --- |
| 强调 `*x*` `_x_` `**x**` `__x__` | 走 CommonMark 的 delimiter stack |
| 删除线 `~~x~~` / `~x~` | GFM；开闭长度必须一致 |
| 代码跨度 `` `x` `` | N 个反引号开闭，N 必须相等；首尾同时有空格时各去掉一个 |
| 链接 `[t](dest "title")` | 支持 `<dest>` 包裹、`'…'` / `(…)` 形式的 title、目标里的配对括号 |
| 图片 `![alt](dest "title")` | 同上 |
| 引用式 `[t][label]` `[t][]` `[label]` | 标签比较大小写不敏感、空白折叠 |
| 自动链接 `<https://…>` `<a@b.com>` | |
| 裸自动链接 | GFM 扩展：正文里的 `https://…`、`www.…` 与邮箱；不吞句末标点与不配对的右括号。`Markdown.AutoLinkPlainUrls="False"` 可关掉 |
| 脚注引用 `[^label]` | 只有存在对应定义时才成立 |
| 硬换行 | 行尾两个空格或反斜杠 |
| 反斜杠转义 | CommonMark 的可转义字符集 |
| HTML 实体 `&amp;` `&#65;` `&#x41;` | 常用命名实体 + 全部数字实体 |

## 几处刻意的取舍

**词内强调。** `get_user_name` 与 `MAX_INT_VALUE` 不会被拆成斜体——这是 CommonMark 的
flanking 规则对 `_` 的额外限制。`*` 没有这条限制，所以 `a*b*c` 仍是 `a<em>b</em>c`。
注意 `__init__` 按规范是**加粗**的 `init`，与 `_x_` 的词内限制无关。

**原始 HTML 按「剥标签、留文字」处理，不渲染任意 HTML。** 把原始标签当正文显示既难看
又不安全，因此：

- `<br>` → 换行；`<img src alt title>` → 图片；`<a href>` → 链接
- `<b>` `<strong>` `<i>` `<em>` `<cite>` `<del>` `<s>` `<strike>` → 对应的行内格式
- `<pre>` → 代码块（保留其中的原始格式）
- `<script>` `<style>` `<textarea>` → 整块丢弃
- 其余标签剥掉，标签之间的文字保留

**HTML 实体表只收常用项**（排版、货币、数学、箭头、希腊字母、重音拉丁字母），不是 HTML5
的两千多条全表。表里查不到的名字按 CommonMark 的规定原样保留。

**脚注按定义顺序编号**，不是按引用顺序。文档把脚注写在末尾时两者一致。
脚注定义渲染在它出现的位置，不会被自动搬到文末。正文里的引用记号是一个指向定义的**相对**链接
（`#fn-<label>`），点击默认滚动到对应的 `MarkdownFootnotePresenter`；宿主想自己处理，
在 `Markdown.LinkClicked` 里把事件标成 `Handled` 即可。相对 URI 也保证了它绝不会被交给系统浏览器。

**没有实现**：脚注回到引用点的反向链接、定义列表、`^上标^` / `~下标~`、数学公式、YAML front matter、
目录生成、`{#custom-id}` 标题锚点。

## 流式渲染

模型逐块吐字时用 `AppendText`，不要自己拼 `Text = Text + chunk`——前者保证走「只重解析尾部、
只重排最后一行」的增量路径：

```csharp
markdown.IsStreaming = true;
markdown.AutoScrollToEnd = true;

await foreach (var chunk in response)
{
    markdown.AppendText(chunk);
}

markdown.IsStreaming = false;   // 按最终语义重新解析一次
```

`IsStreaming` 打开的是**乐观闭合**：文档末尾那些「话没说完」的结构按已经闭合来解析。
Markdown 的语义要看到闭合记号才定得下来，少了这层处理，逐字渲染会反复改主意——
`**bold**` 打到一半时先是字面量 `**bold`，再变成斜体 `*bold*`，最后才是粗体，每个粗体词都跳两次。
乐观闭合覆盖：

| 尾部形态 | 流式下的渲染 |
| --- | --- |
| `**bold`、`*it`、`~~del` | 直接按粗体 / 斜体 / 删除线 |
| `` `cod `` | 直接按行内代码，延伸到末尾 |
| ` ``` ` 收尾打了一半（`` `` ``） | 不当作代码内容显示 |
| `\| a \| b \|` + `\|--` | 直接立成表格，剩下的列随输入补齐 |
| `[文字](https://…` 还没闭合 | 目标那截不认成裸链接（免得同一段文字先黑后蓝再变） |

乐观闭合**只作用于文档末尾**：已经闭合的部分语义完全不受影响，
`IsStreaming` 开与关解析出的树对同一段完整文本是相等的。流式结束后务必设回 `false`，
那些始终没闭合的记号会退回字面量。

`AutoScrollToEnd` 的跟随是「粘」在底部而不是每次强拉：用户手动往上滚就停止跟随，
滚回底部附近又恢复——否则流式输出期间没法回看前文。

## 链接定义与流式追加

链接引用与脚注定义是**全文档可见**的：一条写在文末的 `[d]: …` 能改变文档任何位置的解析结果。
这打破了增量解析赖以成立的「顶层块之间没有跨块状态」，所以 `Markdown` 在流式追加时会检查——
文档已经带定义、或这次追加引入了新定义，都退回全量重解析。没有定义的文档（绝大多数流式场景）
仍走只重排尾部的快路径。
